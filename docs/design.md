# 管理画面のデザイン指針 (Channel.io デスク準拠)

2026-11-06 のリデザインで使った指針です。実装ルールの要約は `admin/src/components/README.md` にあり、こちらは方針と画面ごとの構成の根拠を残すためのものです。


対象: /home/chinzo/sokuto の admin SPA (React 19 + react-router + @channel.io/bezier-react 3.6.6 + bezier-icons)。
目的: 見た目と操作感を Channel.io のデスク (desk.channel.io) にできるだけ寄せる。Bezier コンポーネントはそのまま使う (Channel.io 自身のデザインシステムなので、正しく使えば自然に寄る)。独自 CSS は「レイアウトと密度」に限定し、色・角丸・影は Bezier のトークンだけを使う。

## 0. 前提と制約
- 既存ルール: admin/src/components/README.md (CSS レイヤー、1rem=10px、ダークモードは Bezier 変数のみ、i18n は ja/en 両方、横スクロール禁止、860px 以下はモバイル)。
- データ API は変えない (必要なら読み取り系の追加のみ)。`?data=worst|empty|one|huge` の dev フィクスチャ (admin/src/lib/devFixtures.ts) を全ページで通す。
- 製品名の表示は「Sokutō」(i18n `appName`、index.html title、ログイン画面)。識別子 `sokuto` は変えない。
- 新規依存なし。モーション用ライブラリは入れない (CSS transition / @starting-style / Bezier の内蔵トランジションで足りる)。

## 1. デザイン方針 (frontend-design / ui-taste)
Channel.io のデスクは「白いワークスペースを薄いグレーのキャンバスに置き、1px の罫線で区切り、情報密度を高く、主要アクションだけ青」。SaaS カード乱立 (同じ角丸・同じ影のカードの繰り返し) にしない。

トークン (すべて Bezier 変数):
- キャンバス `--bg-grey-lightest`、面 `--bg-white-normal`、ホバー `--bg-black-lighter`、選択 `--bgtxt-blue-lightest`、罫線 `--bdr-black-light`
- 文字 `--txt-black-darkest` (主) / `--txt-black-darker` (副) / `--txt-black-dark` (補助)
- アクセントは青 `--bgtxt-blue-normal` を 1 画面 1 主役に。危険は `--bgtxt-red-*`、成功 `--bgtxt-green-*`、注意 `--bgtxt-orange-*`、シーケンス等の種別は `--bgtxt-purple-*`
- 角丸: 面は `--radius-8`、チップ `--radius-6`、モーダル/シート `--radius-12`。影はフロート要素 (ドロップダウン・シート・浮かせたカード) のみ `--ev-2/3`
- 間隔スケール 4 / 8 / 12 / 16 / 24。行の高さ: リスト行 56px、テーブル行 44px、ナビ項目 34px
- 文字: Bezier `Text` typo 13 (本文)・14 (強調本文)・12 (補助)・16/18 (見出し)。全大文字ラベルや装飾見出しは使わない。数字は tabular。

## 2. シェル (App.tsx / styles.css)
```
┌─220px──────────┬──────────────────────────────────────────────┐
│ [WS▾] 店舗A      │  ページ内容 (余白 24px、幅上限なし。設定だけ 720px)   │
│                 │                                              │
│ 受信箱      12   │                                              │
│ 連絡先          │                                              │
│ 自動化          │                                              │
│ 一斉配信        │                                              │
│ レポート        │                                              │
│ チャネル接続     │                                              │
│ 設定            │                                              │
│ ───────        │                                              │
│ ☀/☾  JA/EN  ⎋  │                                              │
└────────────────┴──────────────────────────────────────────────┘
```
- 左ナビ 220px、背景 `--bg-white-normal`、右罫線。最上部に**ワークスペース切替** (Bezier `Select`/`ListItem` のドロップダウン: 現在のワークスペース名 + イニシャルのアバター + ▾。リストは全ワークスペース + 「ワークスペースを追加」)。切替は `localStorage sokuto:ws` を更新してリロード。
- ナビ項目は Bezier `NavItem` (アイコン + ラベル)。受信箱に未読バッジ (GET /api/overview の未読数 or /api/inbox?filter=unread の件数を 30 秒ごと)。ダッシュボードはナビの最初ではなく「ホーム」として残す (Channel.io に合わせ受信箱を最上位に)。
- 最下部: テーマ / 言語の `SegmentedControl` (xs) とログアウト。現状の `Preferences` を流用。
- モバイル (≤860px): 上部バー 52px (ブランド + ワークスペース名 + メニュー)。ナビは横スクロール (現状維持)。
- ページ上部の `PageHeader`: 高さ 56px の帯 (タイトル 18 bold + 補足 + 右端に主要アクション 1 つ)。下に罫線。

## 3. 受信箱 (Inbox.tsx) — 最重要。Channel.io と同じ 3 ペイン
```
┌─320─────────────┬──────── 1fr ───────────────┬─300──────────────┐
│ 🔍 検索          │ 名前  [LINE] [対応中]  完了▾ │ 基本情報           │
│ [対応中][未読][担当者][完了][すべて] │ ─ 2026/11/06 ─   │  チャネル LINE     │
│ ● 山田 太郎  12:30│   ┌──────────┐              │  状態 対応中       │
│   LINE  最後の… │   │お客様の吹き出し│            │  ボット ● ON      │
│ ○ Jo       昨日 │   └──────────┘              │ タグ  [vip][+]    │
│ …                │              ┌──────────┐   │ フィールド         │
│                  │              │ボット/担当者│   │  phone 090…      │
│                  │              └──────────┘   │ メモ              │
│                  │ [定型文▾] [メッセージ…    送信] │ シーケンス         │
└─────────────────┴────────────────────────────┴──────────────────┘
```
- 左: 検索 (TextField search, 名前/ID の部分一致はクライアント側) + フィルタ **チップ** (`SegmentedControl` ではなく Bezier `Tag`/`Button size xs` の水平チップ列、件数付き)。行: アバター (チャネルアイコンを右下に小さく重ねる = Channel.io の外部メッセンジャー表示) / 名前 / 時刻 / プレビュー 1 行 / 未読ドット / 担当者対応中 (ボット停止) は橙チップ。選択行は `--bgtxt-blue-lightest`。
- 中央: ヘッダ (名前、チャネル、状態チップ、右に「完了にする / 再開する」ボタンとボット Switch)。日付セパレータ。吹き出し: お客様 = 左・グレー面、ボット = 右・白面 + 細罫線、担当者 (human) = 右・青面。システム (follow 等) は中央の小さな灰文字。添付・カード・ボタンチップは現状のまま。失敗は赤罫線 + エラー文。
- 作成欄: 上段ツールバー (定型文ドロップダウン `#`、画像 URL 添付 (既存 imageUrl 対応があれば)、ボット ON/OFF 補助文)、下段 TextArea + 送信。Enter 送信 / Shift+Enter 改行は維持。
- 右: 「ユーザー情報」パネル 300px、セクションは `Divider` で区切り、見出し 13 bold + 折りたたみ (ローカル state)。基本情報 (チャネル、ID、状態、ボット、最終受信/送信、登録日)、タグ (チップ + 追加)、フィールド (KeyValueItem 一覧、空なら「—」ではなく非表示)、メモ (TextArea、blur 保存、既存ロジック)、シーケンス (紫チップ + 解除)。
- モバイル: リスト → 会話 → 「ユーザー情報」はボトムシート (既存のシート CSS を再利用)。
- 操作感: 会話を選ぶと中央と右が即時入れ替わる (アニメなし、Doherty)。送信は楽観的に吹き出しを即表示 (失敗なら赤に)。10 秒ポーリングは維持。

## 4. 連絡先 (Contacts.tsx)
- ツールバー: 検索 + チップ (チャネル / タグ / セグメント) + 右端「セグメント管理」「CSV」。テーブル: アバター+名前 / チャネル / タグ (2 個 + +N) / 主要フィールド / 最終受信 / 状態。行クリックで受信箱へ。空状態は「まだ連絡先がありません。チャネルを接続すると…」+ チャネル接続への導線。

## 5. 自動化 (Flows.tsx)
- テーブル行: 名前 (+ シーケンス紫チップ) / 公開 Switch (インラインで publish/unpublish、楽観的更新) / トリガー要約 / チャネル / 更新日時 / … メニュー (複製は無ければ省略、削除)。上部に「新しい自動化」「シーケンスを作成」「テンプレートから」。テンプレートはモーダルのカードグリッド (名前 + 説明 + チャネル)。
- エディタ (FlowEditor/Canvas) は直近で作り直したので構造は変えない。ノードの見た目だけトークンに合わせて微調整可 (ヘッダー行に種別アイコン + 種別名、本文 12px、選択は青 2px)。

## 6. 一斉配信 / レポート / チャネル接続 / ダッシュボード
- 一斉配信: 左にフォーム (幅 480) / 右に一覧ではなく、上部に「新しい配信」ボタン → 右ドロワー (420px) でフォーム。一覧テーブルは状態チップ・対象・送信/失敗/クリック数 (tabular)。
- レポート: 期間 `SegmentedControl` (7/30/90 日)、上段に StatCard 4 枚、下に自動化ごとのテーブル。
- チャネル接続: チャネルごとの行カード (ロゴ代わりのアイコン、名前、接続状態チップ、「設定」で展開)。Webhook URL はワークスペース ID 付きを `CopyBox` で。
- ダッシュボード: 今日の未読 / 7 日の新規 / 送受信 / 公開中の自動化の StatCard、最近の通知、次の一手 (チャネル未接続 → 接続、自動化 0 → テンプレート)。

│ ワークスペース  │  ボット名 / 言語 / タイムゾーン   │
│ ボット変数     │  …                           │
│ 定型文        │                              │
│ AI 応答       │                              │

## 8. モーション (animate / animation-performance / apple-design)
- 原則: ユーザー操作への応答だけ動かす。ページ遷移・一覧表示にエントランスアニメは付けない。
- 値: ドロワー / シート 220ms `cubic-bezier(0.32, 0.72, 0, 1)`、ドロップダウンは Bezier 任せ、ボタン押下は Bezier 任せ、ホバー 120ms `ease`、チップ選択 120ms。`transform` / `opacity` のみ。`transition: all` 禁止。
- シートはドラッグでなく閉じるボタン + スクリム (ジェスチャーは今回やらない)。`prefers-reduced-motion` ではスライドをフェードに。`@media (hover: hover)` でホバー効果をゲート。
- 送信・保存などの非同期は 400ms 以内に何か反応 (ボタン loading、楽観的 UI、Skeleton は Bezier に無いので `LoadingState compact` を行数分の薄い面で代替)。

## 9. UX 原則 (web-app-ux)
- 1 画面 1 主役 (青いボタンは 1 つ)。破壊的操作は赤 + ConfirmModal。
- 空状態は「次にすること」を示す (ボタン付き EmptyState)。エラーは原因と対処を文で。
- タップ目標 ≥ 44px (行、チップは 32px 高でも間隔 8px)。
- 入力は寛容 (全角数字、スペース、改行)。
- 用語統一: 受信箱 / 連絡先 / 自動化 / 一斉配信 / レポート / チャネル接続 / 設定 / ワークスペース。「保存」→ トースト「保存しました」、「公開する」→「公開しました」。

## 10. 品質の床と検証
- 全ページを 1280px と 390px、ライト / ダーク、`?data=worst|empty|one|huge` で確認 (break-ui)。横スクロール 0、はみ出し 0、アバター潰れ 0、"1 members" 型の複数形ミス 0。
- キーボード: フォーカスリング可視、Esc でシート / ドロワーを閉じる、Enter 送信。
- コントラスト 4.5:1 以上 (Bezier の txt トークンは満たす)。
- web-design-guidelines: https://raw.githubusercontent.com/vercel-labs/web-interface-guidelines/main/command.md を取得して、変更した tsx/css をレビューし、指摘を直してから完了とする。
- 変更後に Playwright でスクリーンショットを撮り、Channel.io 風になっているか (白い面、罫線、密度、青は 1 つ) を自分の目で確認する。
